# UHMS Reports, Analytics, Export & Print Standardisation

Date: 2026-06-12

## Audit Findings

UHMS already had a reporting layer. The phase reused:

- `ReportRegistryService` for the Reports Hub catalogue.
- `OperationalReportService` and `OperationalReportController` for cross-module operational reports.
- Existing report routes under `admin.reports.*`, accounting routes, AR/AP routes, emergency reports, blood bank reports, and activity-log routes.
- Existing Blade views in `resources/views/reports/`, `resources/views/accounting/reports/`, and `resources/views/billing/reports/`.
- Existing export packages: `maatwebsite/excel` and `barryvdh/laravel-dompdf`.
- Existing `x-print-layout`, Bootstrap 5, Tabler Icons, Chart.js/ApexCharts assets, and EN/FR report language files.

No parallel report module, new UI framework, new chart library, or new export package was introduced.

## Implemented

- Added reusable report infrastructure:
  - `ReportPermissionService`
  - `ReportFilterService`
  - `ReportExportService`
  - `ReportPrintService`
- Updated `ReportRegistryService` so the report hub now checks enabled modules as well as route existence and permissions.
- Standardised operational report filtering with validated date/status/department/user/patient/visit/blood-group inputs.
- Added current-month default date range for operational reports to avoid unbounded report execution.
- Added CSV metadata rows: hospital identity, generated by, generated at, and filter summary.
- Added print rendering for operational reports through the existing `x-print-layout`.
- Added permission-aware UI hiding for operational CSV and print actions.
- Added service-level redaction for restricted report columns:
  - sensitive diagnosis/complaint text requires `reports.clinical_sensitive.view`
  - billing and claims monetary columns require `reports.financial_values.view`
- Added standard report permissions to `RoleSeeder` without removing legacy route permissions.
- Added permission metadata for sensitive financial, stock cost, and clinical report permissions.
- Added EN/FR filter keys for generated CSV/print filter summaries.

## Routes Updated

No route names were changed. Operational reports continue to use the existing `admin.reports.{report}` routes. CSV export and print are selected with query parameters:

- `?export=csv`
- `?print=1`

Backend authorization is enforced for both actions.

## Export Behaviour

Operational CSV exports:

- respect filters
- respect report permissions
- include hospital identity
- include generated by/generated at
- include filter summary
- use translated headings
- exclude restricted columns before output
- cap export rows through the existing operational report service limit

Excel/PDF exports already present in legacy reports were left intact.

## Print Behaviour

Operational print pages:

- use `x-print-layout`
- show hospital identity
- show report title
- show generated by/generated at
- show filter summary
- render black-on-white report tables
- exclude restricted columns before output

Existing invoice, receipt, prescription, lab, claims, accounting, and PDF report views were not rewritten.

## Performance Notes

- Operational report filters now default to the current month.
- Screen reports remain paginated.
- CSV exports continue to use the existing 5,000-row cap in `OperationalReportService`.
- No destructive migrations or new indexes were added.
