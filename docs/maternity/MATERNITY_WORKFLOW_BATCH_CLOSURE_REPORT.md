# Maternity Workflow Batch Closure Report

## Scope

Phase 13 closes the current Admission/Ward/Maternity strengthening batch by adding reporting, CSV export, billing mapping readiness, manual test data, permissions, localisation, documentation, and regression coverage.

The completed maternity chain remains:

Pregnancy Profile -> ANC Visits -> Labor Episode -> Labor Observations -> Delivery Record -> Newborn Records -> Postnatal Care.

## Existing Workflow Reviewed

The implementation was layered over the existing maternity records and services rather than duplicating them:

- Pregnancy profiles and risk state.
- ANC visits, danger signs, referrals, and admission handoff indicators.
- Labor episodes, observations, stages, escalation flags, and delivery state.
- Delivery records, delivery mode/outcome, maternal condition, blood loss, and newborn-record requirements.
- Newborn records, birth outcome, APGAR, feeding/breathing state, low birth weight, and observation state.
- Postnatal cases, maternal observations, newborn observations, readiness, referrals, and follow-up dates.
- Existing admission, discharge readiness, dashboard, permission, localisation, route, export, and manual seeder conventions.

## Implemented Components

### Reports

Added `App\Services\Maternity\MaternityReportService` to keep report calculations and row queries out of Blade views.

Reports added under `admin/maternity/reports`:

- Antenatal report.
- Labor report.
- Delivery report.
- Newborn report.
- Postnatal report.
- Cross-maternity risk and safety report.

Each report supports practical filters for date range, department, staff, status, risk, outcome, referral/readiness, delivery mode, newborn outcome, and admission-linked workflows where relevant.

### CSV Export

Added `App\Services\Maternity\MaternityReportExportService`.

CSV export is available for:

- ANC.
- Labor.
- Deliveries.
- Newborns.
- Postnatal.
- Risk.

Exports include application metadata, generated by/time metadata, active filters, column headings, and report rows. No PDF or spreadsheet dependency was added.

### Billing Mapping Readiness

Added `App\Services\Maternity\MaternityBillingReadinessService`, `App\Models\MaternityServiceMapping`, and the `maternity_service_mappings` table.

The readiness page tracks configuration for:

- ANC registration/package.
- ANC follow-up.
- Maternity admission.
- Labor observation.
- Normal delivery.
- Assisted delivery.
- Caesarean/theatre handoff.
- Delivery consumables.
- Newborn care.
- Neonatal observation.
- Newborn resuscitation.
- Postnatal mother care.
- Postnatal newborn care.
- Immunisation placeholder.
- Ultrasound placeholder.
- Maternity consumables.

The page shows missing mappings, mapped service name/code, inactive services, duplicate service mappings, configured user/time, and safe warnings.

Important: this phase does not create invoices, invoice items, journal entries, stock usage, pharmacy dispensing, or historical billing recalculation.

### Manual Test Data

Added `App\Services\Maternity\MaternityManualTestDataService` and the command:

```bash
php artisan maternity:seed-manual-test-data --count=3 --fresh-manual --force
```

The command creates explicitly identifiable `MT-MAT-` records for manual testing:

- Maternity department/staff.
- Mother patient and visit.
- Admission, ward, and bed context.
- Pregnancy profile.
- ANC visit.
- Labor episode and observation.
- Delivery record.
- Newborn record or records.
- Postnatal case.
- Maternal and newborn postnatal observations.

The command is guarded against production use and is not called by default seeders.

### Permissions

Added permissions:

- `maternity.reports.view`
- `maternity.reports.export`
- `maternity.billing_readiness.view`
- `maternity.billing_readiness.manage`
- `maternity.manual_seed.run`

The maternity clinical role receives report/export/readiness-view access. Billing readiness management and manual test seed execution remain administrative capabilities.

### Localisation

Added English and French keys for report labels, filters, billing readiness warnings, manual seed output, and Phase 13 navigation text.

## Protected Workflows

The following workflows were intentionally not rewritten:

- Admission request lifecycle.
- Admission creation.
- Discharge readiness.
- Emergency workflow.
- Theatre workflow.
- Pharmacy dispensing.
- Stock consumption.
- MAR and nursing care.
- Existing billing posting and accounting behavior.

## Known Risks

- Reports are operational summaries, not a clinical decision engine.
- Billing mapping readiness depends on the service catalog being maintained accurately.
- The manual seed command is intentionally local/manual-test oriented and should not be used as live clinical data.
- CSV exports are simple and safe; very large datasets may need queued exports in a future reporting batch.
